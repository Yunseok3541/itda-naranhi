# 기능을 바로 알아보게 하기 — 자료 조사 (2026-11-21)

> 브랜치 `feat/feature-discoverability`. 제안 1·2번 일부를 구현함 (아래 6절).
> 문제: 지금 기능들이 무슨 기능인지 사용자가 바로 알기 어렵다.

## 1. 이 문제를 부르는 말

- **발견 가능성(discoverability)**: 이게 뭔지, 누를 수 있는지, 누르면 어떻게 되는지를 설명 없이 알아채는 정도
- **단서(signifier)**: 누를 수 있는 것은 누를 수 있게 보여야 함 (Don Norman)
- **기억 말고 보고 알게(recognition over recall)**: Nielsen 사용성 원칙 6번

## 2. 일반 원칙 (효과가 확인된 순서)

| 방법 | 내용 | 근거 |
| --- | --- | --- |
| ① 아이콘 옆에 글자 이름을 항상 | 눌러야·올려야 나오는 이름은 폰에서 소용없음 | NN/g. 다른 연구: 이름 있을 때 결과 예측 88%, 없을 때 60% |
| ② 누를 수 있는 건 누를 수 있게 | 테두리·그림자·화살표 같은 단서 | NN/g 시선 추적: 단서가 약하면 더 오래 보고 더 헤맴 |
| ③ 멋진 이름보다 쉬운 이름 | 직접 만든 말·내부 용어는 사용자가 모름 | NN/g "Category Names Suck", "3 IA Mistakes" |
| ④ 처음 튜토리얼 대신 그 자리에서 한 줄 | 그 기능을 처음 만날 때, 한 번에 하나, 닫을 수 있게 | NN/g 70명 연구: 앱 소개 튜토리얼 본 사람이 과제를 더 어렵게 느끼고 성공률·속도 차이 없음. 코치마크도 같음. Apple도 상황별 팁 권장 |
| ⑤ 빈 화면에 할 일 안내 | 무슨 상황인지·다음에 뭘 하면 되는지 | NN/g: 완전히 빈 화면은 "고장 났나?" |
| ⑥ 숨은 손동작(끌기·확대)은 알려주기 | 모르면 시도조차 안 함. 몇 초 떴다 사라지는 안내 | Baymard: 확대 지원 사이트의 절반만 알려줌 |
| ⑦ 단계적으로 보여주기 | 자주 쓰는 것만 보이고 나머지는 접기·더보기 | NN/g. 우리 앱은 이미 사용 중 |

## 5. 제안 순서 (권장)

1. **이름 정리 + 결과의 의미 한 줄**: 비용이 가장 적음 (포인트, 하늘 지도/모든 별 보기/도감, 직접 만든 말)
2. **처음 한 번만 비춰 알려주기**: 하늘 끌기, 별 누르기, 별똥별. 한 번에 하나, 최대 3개, 닫을 수 있게, 다시 안 나오게
3. **누를 수 있는 것만 은은한 움직임**: 사라진 애니메이션 중 단서 역할을 하던 것 되살리기
4. **배치 점검**: 도움받을 곳 위치, 가운데 버튼 성격, 메인 밖에서 정책·센터로 가는 길 (팀 규칙과 부딪혀 팀 상의 필요)
- 하지 않을 것: 여러 장짜리 소개 튜토리얼 (연구에서 효과 없음)

## 6. 구현한 것 (11/21)

| 무엇 | 어떻게 | 파일 |

| 처음 한 번 안내 카드 (최대 3개, 한 번에 하나) | ① 끌기: "하늘을 끌어서 둘러보세요" → 하늘을 직접 끌거나 "알겠어요"로 끝 ② 별: "반짝이는 별을 눌러 보세요" + 지금 별자리의 안 만난 별이 은은하게 숨 쉼 → 별을 누르거나 "알겠어요"로 끝. 멀리서 볼 땐 "가까이 보기"(별이 위 버튼 뒤에 숨는 작은 화면 대비) ③ 별똥별: 첫 별똥별 옆에 "눌러서 +1" → 그 별똥별이 지나가거나 잡으면 끝 | `lib/sky-hints.ts`, `components/night-sky.tsx`, `components/meteor-rewards.tsx` |
