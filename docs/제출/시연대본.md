# 심사위원 시연 대본

목표 시간 2분. URL은 윤석이 로그아웃 브라우저로 확인한 주소를 07장에 넣는다. 아래는 목표 동선이다. 가상 입력만 사용하고, 재희는 실제 API에 연결한 화면을 캡처한다. 더미 모드는 개발 리허설용으로 표시한다.

| 순서 | 누를 곳과 가상 입력 | 심사위원에게 보여줄 변화 | 캡처 |
| --- | --- | --- | --- |
| 1 | 새 브라우저 → 데모 시작 → 집 앞 / 사람 만나기 / 혼자 하는 활동 → 북쪽왕관자리 선택 | 가능한 범위를 직접 정한다. | A 시작 별자리 |
| 2 | 체크인 → “오늘은 집 근처까지는 나갈 수 있을 것 같아요.” → 집 근처 → 마음 날씨 보기 | 날씨와 오늘 선택이 따로 보인다. 필요하면 날씨를 직접 바꾼다. | B 체크인 결과 |
| 3 | 오늘의 별 → 추천 이유를 읽고 ‘현관 앞 5분 서 있기’ 선택 | 시드에 있는 작은 행동이 오늘 선택과 연결된다. 리허설에서 이 별이 없으면 실제 추천된 2단계(현관·집 앞) 별로 진행하고 회고도 그 행동에 맞춘다. | C 제목·추천 이유 |
| 4 | 손 뻗어 보기 → 몸이나 마음이 힘들었어요 → “현관문을 열고 잠깐 서 봤어요.” → 회고 저장 → 여기서 마치기 | 목표를 다 채우지 않아도 시도가 기록된다. 다음 행동 선택이 아직 구현 전이면 저장까지만 시연한다. | D 두 버튼·기록 결과 |
| 5 | 내 밤하늘 → 브라우저 새로고침 → 방금 손 뻗어 본 별 누르기 | 별이 남아 있고 눌렀을 때 날짜와 방금 입력한 원문을 다시 읽을 수 있다. | E 새로고침 후 별과 회고 |

발표 멘트 — “오늘은 집 앞까지 나가볼 수 있다고 했습니다. 현관문은 열었지만 5분을 채우지는 못했어요. 내일 앱을 다시 열었을 때도 오늘 어디까지 가 봤는지가 남습니다.”

## 후속 장면 · 센터 앞에서 돌아온 날

1. 센터 목록에서 시연용 센터 상세를 연다. 실데이터면 출처·기준일, 가상이면 ‘예시 데이터’가 함께 보이는지 확인한다.
2. **앞까지 가 보기 → 직접 도착 기록**을 누른다. 센터 앞까지 간 별이 켜진다. 문의나 프로그램 참여 횟수가 늘어나면 수정한다.
3. “센터 앞까지 갔는데 문을 열기는 어려웠어요.”를 남긴다. **문의 문장 준비하기**에서 “처음인데 예약 없이 들러도 되나요?”를 고른다.
4. 초안 예시 “안녕하세요. 처음 방문하려고 하는데 예약 없이 들러도 될까요?”를 확인하고 **초안 저장**에서 끝낸다. F 캡처는 센터의 두 선택지, G는 저장된 초안이다. 장소·운영시간·문의 전송을 꾸며내지 않는다.

## 리허설 기록

| 확인할 장면 | 인수 조건 | 증빙 담당 |
| --- | --- | --- |
| 새로고침·세션 | A 브라우저에서는 회고가 남고 새 B 브라우저에서는 A 회고가 보이지 않는다. | 윤석 · URL, 커밋, 확인 시각 |
| 저장 실패·AI 대체 | 입력 유지·재시도·도움 안내를 확인하고 AI 기본 응답을 실제 AI 성공과 구분한다. | 은비 · 가상 요청과 응답 |
| 휴대폰 | 갤럭시·아이폰에서 버튼을 누르고 키보드를 닫아 회고를 저장한다. 에뮬레이션이면 그렇게 기록한다. | 재희 · 기기·브라우저·캡처 |
| 발표 반영 | 수혁이 첫 방문부터 E까지 독립적으로 재현하고 07장에 확인한 장면만 넣는다. | 수혁 · 리허설 일시·결과 |

현재 A~G는 촬영 목록이다. 실제 화면과 증빙은 통합 후 채운다.
