# 나란히 프로젝트 소개서 원고

공식 첨부2의 프로젝트 요약과 01~08을 본문 9장으로 구성한다. 표지는 “나란히 — 오늘 할 수 있는 한 걸음을 별에 담는 AI 퀘스트”, 대표자 채수혁, 팀원 최윤석·고은비·김재희로 작성한다. 공식 팀명과 실제 제출일은 대표자 확인 후 기입한다. 작성 안내 페이지는 PDF에서 제외한다.

| 본문 / 양식 | 발표에도 읽을 수 있는 원고 | 넣을 화면·그림 |
| --- | --- | --- |
| 1 · 프로젝트 요약 | 집 밖에 나갈 마음이 있어도 어디까지 해볼지 정하기는 어렵습니다. 나란히는 오늘 가능한 활동을 묻고 작은 행동 하나를 별로 제안합니다. 기준 커밋에는 체크인·날씨 수정 API와 별 16개의 시드가 있습니다. 키워드는 한 줄 체크인, 작은 시도, 다시 찾는 회고입니다. | 1단계에서는 시드 별 카드 예시를 ‘설계 예시’로 표시. 통합 후 밤하늘 캡처 E |
| 2 · 01 문제 정의 | 가까운 청년센터를 알아도 첫 방문에 무엇을 물을지, 어디까지 가야 할지 막막할 수 있습니다. 현관 앞까지 갔다가 돌아온 사람이 다음에도 같은 목표만 받으면 오늘의 시도가 다음 걸음에 쓰이지 않습니다. | ‘센터를 찾음 → 입구에서 망설임 → 다음에 할 일’ 세 장면. 가상 사례 표기 |
| 3 · 02 대상 사용자 | 가상 사용자 민수(26)는 혼자 집 앞까지 갈 수 있지만 낯선 사람과 대화하기가 부담스럽습니다. 민수는 오늘 가능한 범위를 고르고, 힘들었던 이유를 기록하고, 다음 방문 전에 물어볼 문장을 준비할 수 있습니다. 청년센터는 향후 안내 채널로 검토합니다. | 시작 질문과 사용자 선택 A |
| 4 · 03 AI를 활용한 해결 방안 | 짧은 회고에는 같은 행동에서 멈춘 서로 다른 이유가 담깁니다. ‘비가 왔어요’에는 다른 날을, ‘사람이 많았어요’에는 한산할 때 입구까지만 가보기를 제안하도록 설계했습니다. 체크인에서는 모델이 날씨·위험 신호를 정해진 형식으로 돌려주고, 서버가 형식을 검사해 규칙 결과와 합칩니다. | B와 이유별 제안 두 개. 추천 실행 전에는 ‘설계 예시’ 표시 |
| 5 · 04 서비스 구조 | 모바일 브라우저가 Next.js 화면과 같은 앱의 API를 사용합니다. 서버에서 Gemini를 호출하고 PostgreSQL에 체크인을 기록합니다. 배포 구성은 Vercel과 Neon입니다. 공공데이터는 출처 확인 후 센터·정책 화면에 연결할 계획입니다. | [서비스 구조도](서비스구조도.md). 하단에 Next.js/React, Route Handler, Gemini(실호출 모델 확인 후 기입), PostgreSQL, 외부 API 사용 상태와 데이터 조건 표기 |
| 6 · 05 핵심 기능 및 사용자 흐름 | 세 가지 행동을 보여줍니다. ① 오늘 가능한 범위를 고르고 마음 날씨를 확인합니다. ② 추천받은 별에서 ‘하늘의 별 따기’ 또는 ‘손 뻗어 보기’를 고릅니다. ③ 회고를 저장한 뒤 별을 눌러 그 날의 기억을 읽습니다. | B → C → D → E. 통합 전은 목표 흐름으로 표시 |
| 7 · 06 차별점 | 완료 여부만 기록하면 5분을 채우지 못한 시도의 이유를 알기 어렵습니다. 나란히에서는 현관에 잠깐 선 날에도 기억을 남기고 다음 행동을 바꿀 수 있습니다. 센터 앞까지 가기, 문의 초안 작성, 실제 참여도 각각 따로 기록하도록 설계했습니다. | 같은 시도에서 ‘다른 날’과 ‘더 작게’로 갈라지는 예시. 특정 경쟁사 기능에 관한 단정 제외 |
| 8 · 07 구현 현황 및 프로토타입 | 11/19 기준 체크인, 날씨 수정, 상태 확인 라우트와 Gemini 응답 검증·기본값 코드가 있습니다. DB 시드에 별자리 3개와 별 16개가 있습니다. 기본 페이지 상태이며 추천부터 밤하늘까지의 실제 배포 시연은 통합 검증 대상입니다. | 제출 직전 이 문장을 갱신한다. 검증한 URL, 확인 시각·커밋, E 캡처, 첫 클릭 ‘데모 시작’을 기입한다. 선택 영상은 3분 이내 |
| 9 · 08 기대효과 | 사용자가 작은 시도를 다시 해보고, 원할 때 청년센터 문의까지 준비하는 것이 목표입니다. 첫 지표는 ‘앱 밖 활동을 한 번이라도 시도한 사용자 ÷ 전체 사용자’로 설계했습니다. 이어서 다음 행동 선택 후 재시도와 센터 행동별 기록을 살펴봅니다. | 지표 정의와 수집 시점. 가상 시연 기록을 실제 효과 수치로 제시하지 않는다. |
