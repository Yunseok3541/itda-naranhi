## 2. 선택 이유

### 모바일 웹 + Next.js 하나로 (고민기록 #27)
- 앱스토어 배포 없이 브라우저에서 바로 실행
- 화면과 서버 API를 한 프로젝트에서 처리 → 팀에 익숙한 스택이 없어서 **배울 것을 하나로 줄임**, 프론트·백엔드 연결(CORS, API 주소) 설정 불필요
- 역할 분담은 프로젝트가 아니라 폴더로: 화면 `web/src/app/(화면)`, API `web/src/app/api/`, 공통 로직 `web/src/lib/`
- 이미 동작하는 체크인 API, 위험 판단, Gemini 호출 코드를 그대로 사용
- ⚠ Next.js 16은 최신 버전이라 인터넷 자료와 다른 부분이 있음 → `web/node_modules/next/dist/docs/` 확인 (web/AGENTS.md)

### Vercel 배포
- GitHub에 푸시하면 자동 배포, HTTPS 고정 주소(`*.vercel.app`) → **GPS(브라우저 위치)와 카카오맵 도메인 등록 조건 충족**
- 서버리스라 무료 서버처럼 "잠드는" 문제가 없음 (첫 요청만 조금 느릴 수 있음)
- 내 컴퓨터를 켜 둘 필요 없음
- Gemini·공공 API 키를 서버 쪽에 두어 브라우저에 노출하지 않음

### Gemini 무료 API
- 프로토타입 단계에서 비용 0원
- JSON 스키마로 응답 형식을 강제할 수 있어서 AI 결과를 앱이 바로 검증해 사용 가능
- 모델 이름은 환경 변수(`GEMINI_MODEL`)로 분리 → 무료 등급 모델이 바뀌어도 코드 수정 없음

### PostgreSQL: 배포는 Neon, 로컬은 Docker 또는 Neon
- AI 결과(JSON)를 JSONB로 저장·조회하기 편함
- 스키마는 루트 `db/init/*.sql` 하나로 관리 → Neon과 로컬 Docker에 같은 SQL 실행
- 배포 DB: **Neon 무료**. 쉬면 잠들지만 1초 안팎으로 깨어나 시연에 지장 없음. 서버리스 환경이므로 **연결 풀(pooled) 주소** 사용
- 로컬 개발: `docker compose up -d`(Docker Desktop 필요) 또는 Docker 없이 Neon에 개발용 DB(브랜치)를 하나 더 만들어 연결

## 3. 검토했지만 고르지 않은 것

| 후보 | 고르지 않은 이유 |
| ---- | ---------------- |
| Claude API | 품질은 좋지만 유료. 비용 0원 원칙에 맞지 않음 |
| Supabase 무료 | 일정 기간 사용이 없으면 프로젝트가 일시정지되어 시연 당일 위험 |
| React(Vite) + Express, Vercel 프로젝트 2개 (A안) | 프론트·백엔드를 프로젝트로 나눌 수 있지만, 익숙한 스택이 없는 팀에겐 배울 것과 연결 설정이 늘어남 (#27) |
| 무료 서버(Render 등)에 백엔드 | 15분 동안 요청이 없으면 잠들어 첫 응답이 수십 초 → 시연 위험 |
| 서버 1대 + Docker Compose (EC2 등) | SSAFY 서버 제공 없음, 비용과 HTTPS·도메인 직접 설정 부담 |
| 로컬 실행 + cloudflared 터널 | 내 컴퓨터를 계속 켜 둬야 하고, 주소가 매번 바뀌어 카카오맵 도메인 등록 불가 |
| SQLite 파일 | 로컬은 편하지만 배포 시 데이터 유지가 안 됨 |
| React + Spring Boot | 익숙한 사람이 없고, 서버 두 개를 띄우고 연결해야 해서 속도가 느림. 무료 서버에서 메모리·시작 시간도 불리 |
| 네이티브 앱 | 개발·설치 부담이 큼. 웹으로 카메라·위치 사용 가능 |

## 4. AI 기능별 구현 방식

| # | 기능 | 방식 | 실패 시 |
| - | ---- | ---- | ------- |
| ① | 오늘의 별 추천 + 시도한 별 다음 행동 | 서버 API에서 호출, 단계별 퀘스트 목록 안에서만 고르게 함. 추천은 **하루 한 번만 생성해 저장**. 손 뻗어 보기 이유 → 더 작게 / 다른 날 / 다른 별 / 마치기 제안 | 추천: 현재 별자리의 다음 별 / 다음 행동: 다른 날 그대로 하기 |
| ② | 체크인 → 마음 날씨 | 서버 API에서 호출, 날씨는 정해진 값 중 하나 (참고 기록, 난이도는 사용자의 `today_choice` 우선) | 보통(구름 조금) |
| ③ | 위기 표현 안내 | **키워드 규칙(직접·간접 2단계) 먼저**, 그다음 AI. 둘 중 더 위험한 쪽 채택. 체크인·회고 등 모든 문장 입력에 적용 | 규칙 + 부정 감정 표현으로 판단, 최소 주의 (`assessRisk`) |
| ④ | 회고 맞춤 응원 | 서버 API에서 호출, 한두 문장 | 미리 써둔 기본 응원 |
| ⑤ | 정책 분류 | **미리 스크립트로 한 번 분류해 DB 저장**, 앱은 저장된 결과만 조회 | 분류 안 된 정책은 노출 안 함 |
| ⑥ | 문의 문장 초안 | 서버 API에서 호출, 센터·프로그램 정보에 있는 내용만 사용, 초안으로 저장(`inquiry_drafts`) | 기본 문의 문장 틀 |

공통: 모든 AI 호출은 `web/src/lib/gemini.ts`의 `generateJson`을 거침 (JSON 스키마 + 검증 + 기본값)

### 테이블 구성

| 구분 | 테이블 | 역할 |
| ---- | ------ | ---- |
| 사용자 | `users` | 닉네임, 시작 질문 답(`start_answers`), 추천 기준 단계, 지역, 같은 하늘의 별 동의 |
| | `survey_results` | 선택형 마음 짚기 응답과 점수 (레벨·위험 판정에 쓰지 않음) |
| 콘텐츠 | `constellations` | 별자리 (단계 = 숨겨진 난이도) |
| | `stars` | 별 = 퀘스트, 인증 방식, 퀘스트 종류(일상/청년센터/봉사), 집 밖 활동 여부(`is_outside`) |
| | `sub_quests` | 더 작게 해 보기용 하위 퀘스트 목록 (AI는 이 안에서만 고름) |
| 진행 기록 | `user_constellations` | 고른 별자리, 완성 시각(= 도감) |
| | `star_attempts` | 별 시도 기록 (희미한 별·밝은 별, 이어진 시도, 쪼갠 별, 회고, 응원, 회고 위험도, 손 뻗어 보기 이유와 다음 행동, GPS 장소) |
| | `checkins` | 한 줄 체크인, AI 날씨·사용자가 고친 날씨, 오늘 선택, 위험도 |
| | `daily_recommendations` | 하루 한 번 생성한 오늘의 별 추천 (날짜는 한국 시간, 별마다 이유 `items`) |
| | `inquiry_drafts` | AI ⑥ 문의 문장 초안, 실제 문의는 사용자가 직접 기록 |
| | `center_events` | 청년센터 상세 보기, "참여했어요" 직접 기록 |
| 공공 데이터 | `policies` | 청년정책 + 복지서비스, AI 분류 결과 |
| | `policy_events` | 추천 정책 노출·원문 클릭 기록 |
| | `youth_centers` | 청년센터와 좌표, 운영시간·프로그램, 출처·기준일·이용 조건, 예시 구분 |

- `policies`, `youth_centers`는 공공 API에서 미리 수집한 참고 자료라 사용자 테이블과 외래키로 묶지 않음. 사용자와는 지역 코드(`region_code`)로 조회할 때 연결
- ERDCloud 확인용 MySQL DDL: `db/erdcloud.sql`

### 설계 결정

1. **별 상태를 저장하지 않고 시도 기록에서 계산**
   - `star_attempts`에 시도할 때마다 한 줄씩 쌓고, 상태는 뷰 `v_user_star_status`에서 계산 (완료 기록이 있으면 밝은 별, 시도만 있으면 희미한 별, 없으면 꺼진 별)
   - 실패도 지워지지 않는 기록이 된다는 기획 원칙과 맞음
2. **손 뻗어 보기 뒤 다음 행동은 새 별을 만들지 않고 "이어진 시도"로 기록**
   - 손 뻗어 보기(dim) 줄에 AI 제안(`suggested_action`), 사용자 선택(`next_action`), 고른 대상(`next_sub_quest_id`·`next_star_id`)을 저장 → 다시 시도하기 전에도 "다음에 할 작은 별"이 남고, AI 제안을 따랐는지 볼 수 있음
   - 이어진 시도는 `parent_attempt_id` = 원래 시도. 더 작게 해 보기는 원래 별 + 하위 퀘스트(`sub_quest_id`, 이름 사본 `custom_title`), 다른 날 그대로 하기는 같은 별, 다른 별로 바꾸기는 새 별
   - 하위 퀘스트는 미리 정한 `sub_quests` 목록에서만 (복합 외래키로 "그 별의" 하위 퀘스트만 허용, 자유 문장 이름은 거절) → 기획 6장 "미리 정한 범위 안에서만"
   - 하위 퀘스트를 완료하면 원래 별이 밝아짐 → 별자리 별 개수가 바뀌지 않음
   - 원래 시도나 체크인을 지워도 이어진 시도·추천은 남음 (`ON DELETE SET NULL`, 기획 7장 "언제든 기록 삭제")
3. **오늘의 별 추천은 하루 한 번만 생성해 저장**
   - Gemini 무료 등급 호출 제한을 아끼고, 새로고침해도 추천이 바뀌지 않음
4. **정책은 원본(JSONB)과 AI 분류 결과를 함께 저장**
   - 프롬프트를 고치면 원본으로 다시 분류 가능
   - 나이·지역·신청 기간은 컬럼으로 두어 규칙 필터로 확실하게 거름
5. **같은 하늘의 별은 뷰로 모아서만 조회**
   - `v_sky_today`: 동의한 사용자만, 구 단위, 5명 미만이면 결과에서 제외. "오늘"은 한국 시간 기준 (DB 서버는 GMT)
6. **발표 지표를 뷰로 바로 조회** (아이디어_v4.md 8장 효과 측정 지표)
   - `v_outside_attempt_rate`: **1순위 지표**, 앱 밖 활동을 시도한 사용자 비율 (고민기록 #25). 바깥 별(`is_outside`, 센터 "앞까지 가 본 별" 포함) 시도·문의 기록(`sent_at`)·참여 기록(`joined`). 지도·홈페이지 보기 같은 앱 안 청년센터 별은 세지 않음. 분모는 **실제로 시작한 사용자**(시작 질문 답 또는 기록이 하나라도 있음, 데모 시작만 누른 브라우저 제외)
   - `v_next_action_retry_rate`: 보조 지표(AI 효과), 다음 행동(더 작게·다른 날·다른 별)을 고른 뒤 다시 시도한 비율. AI 제안을 따랐는지(`followed_ai`)별로 나눠 봄
   - `v_center_actions`: 보조 지표(지원 연결), 청년센터 행동별 기록 수 (상세 보기·문의 문장 준비·앞까지 가 본 별·문의 기록·참여 기록, 퍼널 아님)
   - `v_split_success`: 하위 퀘스트(더 작게 해 보기)의 완료율
   - `v_policy_click_rate`: 추천 정책 원문 확인 비율 (노출 대비 원문 클릭)
   - `v_policy_click_rate`는 **정보 확인 비율**로 설명 (원문 열람 ≠ 신청·참여)
   - `v_weather_correction_rate`: 사용자가 AI 마음 날씨를 **조정한 비율** (AI 정확도가 아님, 체크인마다 한 번만 집계)
   - 마음 짚기 점수 변화는 `survey_results`에 점검마다 한 줄씩 쌓여서 바로 비교 가능 (선택 응답)
8. **GPS 도착 확인** (고민기록 #21)
   - `stars.verify_type = 'gps'` + `place_type`(목표 장소 종류) → 카카오 로컬로 근처 장소 검색
   - `star_attempts.verify_method`에 실제 확인 방식 기록 (위치를 못 쓰면 self, 불이익 없음)
   - 좌표·이동 경로는 저장하지 않고 `place_id`, `place_name`만 저장
7. **개인정보**
   - 사용자를 지우면 검사·체크인·시도 기록이 함께 삭제됨 (`ON DELETE CASCADE`)
   - 로그인·실명 없이 닉네임만 사용

## 6. 배포·시연 환경

- **배포:** Vercel(프로젝트 Root Directory = `web`) + Neon. 순서는 web/README.md "배포" 참고
- 환경 변수는 Vercel 프로젝트 설정에만 입력 (`DATABASE_URL`=Neon 연결 풀 주소, `GEMINI_API_KEY`, `GEMINI_MODEL`, 카카오 키 등)
- 카카오 개발자 콘솔에 `http://localhost:3000`과 배포 주소(`https://xxx.vercel.app`) 둘 다 등록
- 사진은 선택 기능: Vercel은 서버에 파일을 저장할 수 없으므로 MVP에서는 저장하지 않거나, 필요하면 Vercel Blob 무료 용량 사용
- 정책 수집·AI 분류처럼 오래 걸리는 작업은 **내 컴퓨터에서 스크립트로 한 번 실행해 Neon에 저장** (서버리스 함수 실행 시간 제한 회피)
- 시연: 배포 주소를 휴대폰이나 노트북 모바일 화면으로 열기. 데모용 공공 API 응답과 AI 응답은 미리 저장

## 7. 주의사항
