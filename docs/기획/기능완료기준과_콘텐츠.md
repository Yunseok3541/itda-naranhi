# 나란히 기능 완료 기준과 화면 문구

11월 19일 개발용 문구안. 첫 통합의 종착점은 같은 브라우저에서 별을 다시 눌러 방금 쓴 회고를 읽는 순간이다. 아래는 인수 기준이며, 현재 코드와 실행 증거는 [소개서 07](../제출/프로젝트소개서_원고.md)에 구분한다.

| 화면 | 그대로 쓸 문구와 선택지 | 통과 기준 |
| --- | --- | --- |
| 첫 방문 | **데모 시작** · “가상의 이야기로 체험해 주세요. 실제 개인정보는 입력하지 마세요.” | 새 브라우저로 시작하면 다른 사람의 기록이 보이지 않는다. |
| 시작 질문 ① | “요즘 어디까지 가는 게 편한가요?” 집 안 / 집 앞 / 혼자 외출 / 사람이 있는 곳 | 집 안이면 1단계 별자리(카시오페이아자리·돌고래자리), 집 앞이면 2단계 별자리(거문고자리·토끼자리·여우자리)를 우선 제안한다. 그 밖의 응답은 현재 준비된 별자리 중 직접 고르게 한다. 시작 별자리를 사용자가 확정한다. |
| 시작 질문 ②·③ | “어떤 상황이 부담스러운가요?” 사람 만나기 / 낯선 곳 가기 / 전화하거나 대화하기 / 아침에 일어나기. “어떤 활동을 알아볼까요?” 혼자 하는 활동 / 함께하는 활동도 보기 | 부담 상황은 여러 개 고를 수 있다. 추천 전에 선택 내용을 확인하고 바꿀 수 있다. |
| 오늘 활동 | “오늘은 어떤 활동이 괜찮을까요?” 쉬어 가기(rest) / 집 안(home) / 집 근처(near) / 바깥(out) | rest는 “오늘은 쉬어 갈게요”로 마칠 수 있다. home은 집 안 후보, near는 가까운 후보, out은 선택 가능한 바깥 후보를 우선한다. 체크인 API는 활동 선택 생략도 허용한다. |
| 한 줄 체크인 | “오늘은 어떤 하루인가요?” · “마음 날씨 보기” · “AI가 고른 날씨예요. 다르면 바꿔 주세요.” | 1~300자. sunny 맑음 / partly_cloudy 구름 조금 / cloudy 흐림 / rainy 비 / foggy 안개. 사용자가 수정하면 수정값을 보여준다. 기본값 응답에는 “기본 날씨예요. 지금 마음에 맞게 골라 주세요.”를 쓴다. |
| 오늘의 별 | “오늘 해볼 별을 골라 주세요.” 카드에 시드의 제목과 추천 이유 한 줄. 예시 이유 “집 근처가 괜찮다고 해서 현관에서 해볼 수 있는 별을 골랐어요.” | 실제 후보 1~3개에서 선택한다. AI 실패 시 기존 후보로 제안하고 “준비해 둔 별에서 골랐어요.”를 표시한다. 마음 날씨 수정으로 난이도가 바뀌지 않는다. |
| 별 수행 | **하늘의 별 따기** · “내가 정한 만큼 해냈어요.” / **손 뻗어 보기** · “해보려고 움직였어요.” | 두 버튼을 같은 비중으로 제공한다. 전자는 bright, 후자는 dim으로 기록한다. 위치를 쓸 수 없으면 **직접 도착 기록**으로 같은 별을 남길 수 있다. |
| 회고 | “오늘의 한 걸음을 어떻게 기억하고 싶나요?” · **회고 저장** | 선택한 별과 결과에 회고가 연결된다. 저장 중 중복 클릭을 막고, 성공한 뒤 밤하늘로 이동한다. |
| 밤하늘 | “내 밤하늘” · “아직 만나지 않은 별” / “손 뻗어 본 별” / “따낸 별” · “이 별의 기억” | 모양과 글자로 상태를 구분한다. 새로고침 뒤에도 같은 별에서 날짜와 입력한 회고가 보인다. |
| 포인트 | 별을 처음 땄을 때만 “이 별로 N포인트가 모였어요.” (N = `pointsEarned`). 밤하늘에는 내 포인트 합계(`totalPoints`)만 | 별을 처음 따면 별자리 난이도 × 10(별자리 합계 = 난이도 × 10 × 별 수), 다시 따거나 손 뻗어 보기(dim)는 0이고 감점도 없다. 따기 전 별에는 점수를 보여주지 않는다(숨겨진 난이도). 순위·다른 사람과의 비교·연속 기록 문구는 쓰지 않는다 (고민기록 #31). |
| 유성·체크인 포인트 | 떨어지는 유성을 터치하면 “+1” (`POST /api/meteors`의 `pointsEarned`가 1일 때만), 데일리 체크인을 오늘 처음 마치면 “+100” (체크인 응답 `pointsEarned`가 100일 때만). 밤하늘 합계 `totalPoints`에 함께 더해진다 | 같은 유성은 한 번만, 유성은 하루 20개까지, 체크인은 하루 한 번. 못 받은 경우(이미 받음·한도·지난 유성)는 오류 문구 없이 아무것도 띄우지 않는다. 연속 체크인·체크인 일수 문구는 쓰지 않는다 (고민기록 #32). |
| 저장 실패·도움 | “지금은 저장하지 못했어요. 적어 둔 글은 그대로 있어요.” · **다시 저장하기** | 입력과 선택을 유지한다. 체크인 ID가 없으면 날씨 수정과 추천 진행을 보류한다. help가 있으면 저장 실패 화면에서도 제목과 안내 내용을 표시한다. |

## 돌아온 이유와 이어갈 선택

“어디에서 발걸음이 멈췄나요?” 이유는 선택 사항이다. 아래 문구와 괄호 안 DB 값을 짝지어 쓴다.

| 고르는 이유 | 다음 제안 예시 |
| --- | --- |
| 사람이 많았어요 (crowded) | “다음에는 한산할 때 입구까지만 가볼까요?” |
| 날씨·상황이 안 맞았어요 (weather) | “날이 괜찮은 날 같은 별을 다시 만나볼까요?” |
| 몸이나 마음이 힘들었어요 (tired) | “다음에는 현관문만 잠깐 열어봐도 좋아요.” |
| 시간이 없었어요 (no_time) | “시간이 나는 날 같은 별을 다시 골라도 돼요.” |
| 나랑 안 맞았어요 (not_for_me) | “비슷한 거리에서 다른 활동을 찾아볼까요?” |
| 돈이 들어서요 (cost) | “돈이 들지 않는 다른 활동을 골라볼까요?” |
| 다른 이유가 있어요 (other) | “여기서 마칠까요, 다음에 해볼 일을 고를까요?” |

버튼은 **더 작게 해 보기**(smaller) / **다른 날 그대로 하기**(retry) / **다른 별로 바꾸기**(swap) / **여기서 마치기**(stop). 사용자가 고른 선택을 저장한다. AI 응원이 늦거나 실패하면 bright에는 “오늘 해낸 일을 이 별에 담았어요.”, dim에는 “오늘 손을 뻗어 본 순간을 이 별에 담았어요.”를 쓴다. 저장 성공 뒤에만 이 문구를 보여준다.
