## 2. 시작 질문 (모두 선택, 기본값 "답하지 않을래요")

| # | 질문 | 보기 | 쓰는 곳 |
| - | ---- | ---- | ------- |
| ① | 요즘 할 수 있는 활동 범위는? | 집 안 / 집 앞 / 혼자 외출 / 사람 있는 곳 | **은둔 축.** 시작 단계 (집 안 1, 집 앞 2, 혼자 외출 3, 사람 있는 곳 4 — 초안) |
| ② | 부담되는 상황은? (여러 개) | 사람 만나기 / 낯선 곳 / 전화·대화 / 아침에 일어나기 | 별 추천, 정책 점수 (기존) |
| ③ | 혼자 / 함께하는 활동도 | | 정책 점수 (기존) |
| ④ | 힘들 때 연락할 수 있는 사람이 있나요? | 있어요 / 잘 모르겠어요 / 없어요 | **고립 축.** "없어요" → 상담·마음건강 정책을 조금 앞으로 |
| ⑤ | 지금 누구와 지내요? | 혼자 / 가족과 / 그 밖에 | **생활 형태.** 혼자 → 주거·생활비 정책을 조금 앞으로 |
| ⑥ | 요즘 가장 도움이 필요한 건? (여러 개) | 생활비·일자리 / 몸·마음 건강 / 가족과의 관계 / 사람 만나기 / 잘 모르겠어요 | **지원 방향.** 해당 분야 정책 점수 +2 (가족은 이름·요약에 "가족"이 든 정책). AI 추천 이유에도 전달 |

- 첫 화면에는 ①~③만, ④~⑥은 "내 정보" 화면에서 (처음부터 6개를 묻지 않음)
- **소득은 시작 질문에서 묻지 않음.** ⑥의 "생활비·일자리"로 필요한 방향만
- **유형 이름(고립형·은둔형·가족동거형 등)은 만들지도, 화면에 보여 주지도, 저장하지도 않음** (v4 원칙 "검사 점수로 사람을 나누지 않음")
- ④~⑥은 **별 난이도·단계에 쓰지 않음.** 어떤 지원 정보를 먼저 보여 줄지에만

## 3. 정책 신청 정보 (선택) → 자격 조건 거르기

온통청년 정책 원문에는 나이 말고도 자격 코드가 있다. 사용자가 원할 때만 알려 주면 **확실히 맞지 않는 정책을 추천에서 미리 뺀다.**

| 묻는 것 | 보기 | 원문 코드 |
| ------- | ---- | --------- |
| 출생연도 | 숫자 (15~45세 범위) | 나이 상·하한 (기존) |
| 일하고 있나요? | 일하지 않음 / 회사 / 단기·아르바이트 / 일용직 / 프리랜서 / 자영업 / 창업(준비) / 농업 / 그 밖에 | `jobCd` 0013xxx |
| 학력 | 고졸 전 / 고교 재학 / 고교 졸업 / 대학 재학·휴학 / 대학 졸업 / 대학원 / 그 밖에 | `schoolCd` 0049xxx |
| 결혼 | 미혼 / 기혼 | `mrgSttsCd` 0055xxx |
| 본인 연소득 | 2천만 원 이하 / 2~3천 / 3~5천 / 5~7천 / 7천 초과 | `earnCndSeCd` 0043002 + `earnMaxAmt`(만원) |
| 해당되는 상황 (여러 개) | 기초생활수급·차상위 / 한부모 / 장애 / 자립준비청년 / 가족돌봄 / **해당 없어요** | `sbizCd` 0014003·0014004·0014005 |

### 판단 규칙 (`web/src/lib/policy-eligibility.ts`, AI 없음)

| 경우 | 결과 |
| ---- | ---- |
| 코드가 "제한 없음" | 조건 아님 |
| 코드가 분명하고 내 답과 맞지 않음 (예: 창업자 대상인데 "일하지 않음", 연소득 상한 5천인데 5~7천) | **추천에서 뺌** (`mayNotFit`) |
| 답하지 않음 / "그 밖에" / 코드에 "기타"가 섞임 | 빼지 않고 **"확인할 조건"**으로 표시 (`conditionsToCheck`) |
| 소득이 문장 조건 (기준 중위소득 150% 이하 등) | 가구 기준이라 판단하지 않고 항상 "확인할 조건" |
| 추가 자격 조건 문장 | "확인할 조건"에 줄여서 표시 |

- **"모든 정책 보기"에서는 숨기지 않음.** "조건이 맞지 않을 수 있어요"로 표시만 (원문 데이터가 틀린 경우가 있음, 아래)
- "해당 없어요"(빈 목록)와 "답하지 않음"(null)을 구분: 한부모 대상 정책은 "해당 없어요"면 빼고, 답하지 않았으면 확인할 조건
- 같은 날 정보를 바꾸면 저장된 추천에서 맞지 않게 된 정책만 뺀다. AI를 다시 부르지 않음 (무료 한도, #28)
- **실데이터 확인 (로컬 59개, 2026-11-19):** 정보를 답하지 않으면 빠지는 정책 0개, 확인할 조건이 붙는 정책 25개. "일하지 않음·연소득 2천 이하·미혼·고교 졸업·해당 없음"이면 3개가 빠짐 — 청년 창업자 세무 상담, 청년 한부모 자립 지원, **청년안심주택(원문 코드가 '기혼만'인데 실제로는 미혼 청년도 대상일 가능성 → 원문 데이터 문제. 그래서 "모든 정책 보기"에서는 숨기지 않음)**

## 4. 개인정보

| 원칙 | 적용 |
| ---- | ---- |
| 모두 선택 | 모든 질문에 "답하지 않을래요"가 기본값. 답하지 않아도 시작·추천 모두 됨 |
| AI에 보내지 않음 | 정책 신청 정보(취업·학력·결혼·소득·해당 상황·나이)는 규칙에만 씀. AI에는 ⑥ 필요한 것만 (기존 부담 상황과 같은 수준) |
| 언제든 지움 | "정책 신청 정보 모두 지우기" → DB에서 `NULL` |
| 민감정보 | 거주 형태·건강·소득·수급 여부는 민감정보로 취급 (v4 7장). 시연은 가상 내용만 ("실제 개인정보를 입력하지 마세요") |
| 유형 미저장 | DB에는 답만. 유형 이름이나 점수를 따로 저장하지 않음 |

## 6. 남은 과제

- [ ] 활동 범위 → 시작 단계 대응 확정 (지금은 1·2·3·4 초안. MVP 별자리는 1·2단계뿐이라 3·4로 시작해도 아래 단계 별이 추천됨)

- [ ] 정책 화면 연결 시 `conditionsToCheck`·`mayNotFit` 표시 문구 ("원문에서 확인해 주세요", "알려 주신 정보와 맞지 않을 수 있어요")
