# 개인 맞춤 정책 추천 (AI ⑤)

> **"나에게 맞고, 내가 감당할 수 있는 방식으로 신청할 수 있는 정책"을 이유와 함께 보여 준다.**
> 결정 배경: 고민기록 #6(참여 부담 분류), #7(정책은 퀘스트로 만들지 않음), #20(단계와 관계없이 열람)

## 1. 왜 AI인가

자격(나이·지역·기간)은 규칙으로 거를 수 있다. 하지만 **"이 정책이 고립 청년에게 얼마나 부담스러운가"**(온라인으로 끝나는지, 전화·방문이 필요한지, 여럿이 함께해야 하는지)는 API에 없는 값이다. 신청 방법 문장 속에 섞여 있어 AI가 읽고 판단한다.

## 2. 원칙

| 원칙 | 정책 추천에서 |
| ---- | ------------- |
| 정책은 퀘스트가 아님 (#7) | 신청을 해야 할 일로 만들지 않는다. 보여 주기까지만 |
| 언제든 열람 (#20) | 추천은 난이도로 거르지만, "모든 정책 보기"에서는 전부 보인다 |
| 자격은 규칙으로 | "자격이 됩니다"가 아니라 "확인해 볼 만한 정책". 원문 링크 항상 표시 |
| 클릭 ≠ 참여 (#9) | 지표는 "정보 확인 비율"까지 (`v_policy_click_rate`) |
| 개인정보 | 분류 때 AI에는 공공 정책 문장만. 추천 때는 선택값(부담 상황 등)만, 닉네임·나이·지역·회고 원문은 보내지 않음 |

## 3. 흐름

```
[수집 · 미리]                                 [사용자 요청 · GET /api/policies]
온통청년 정책 API (시연 지역만)                오늘 이미 추천했나? ─예→ 저장된 추천 (AI 0회)
  → 신청 가능·시연 범위로 거르기                 └아니오→ ① 규칙: 지역·나이·마감·개인 이용 가능
  → 저장 (원문 수정 시각이 바뀐 정책만                  ② 참여 난이도: 내 단계 + 1까지 (3개 미만이면 넓힘)
     다시 분류 대상)                                    ③ 점수: 관련도·부담 상황·혼자/함께·최근 멈춘 이유 → 상위 8개
  → 분류 안 된 정책만 AI ⑤ (8개씩 묶음)                ④ AI: 8개 중 3개 + 맞춤 이유 (1회) → 하루 한 번 저장
                                                       (AI 실패 → 규칙 순서 상위 3개 + 문장 틀 이유)
```

- **발표용 설명**: 매일 10시(새로 올라온 정책), 20시(당일 놓친 정책)에 자동으로 확인한다. 새·바뀐 정책만 분류하므로 평소 AI 호출은 0~1번.
- **실제 예약 실행은 추후 과제.** 지금은 `web/scripts/sync-policies.mts`를 직접 실행한다. 예약을 붙일 때는 `syncPolicies()` 하나만 부르면 된다 (Vercel Cron, `CRON_SECRET`으로 보호. Hobby 플랜의 예약 한도는 붙이기 전에 확인).

## 4. 시연 데이터 범위

| 항목 | 값 |
| ---- | -- |
| 지역 | **서울 마포구**(11440, 데모 사용자 기본 지역). API에 `zipCd=11440`으로 요청 → 마포구 청년이 대상인 정책 818개 (2026-11-19) |
| 지역 정책 | 대상 지역 코드가 모두 서울이면 "서울 전체"(`11000`)로 저장. 신청 가능한 29개 모두 |
| 전국 정책 | 중앙부처·산하기관(기관 코드 첫 자리 `1`·`B`)만. 다른 지자체가 모든 지역 코드를 단 정책은 제외. 관련 있어 보이는 순서로 **30개** |
| 신청 기간 | `0057001` 기간 있음(마감 지나면 제외) / `0057002` 상시 / `0057003` 의미 확인 전이라 제외 |
| 중복 | 이름이 같으면(띄어쓰기 무시) 최근 수정된 하나만 |
| 결과 | 59개 저장, 개인이 이용할 수 있는 정책 49개 (나머지 10개는 실태조사·시스템 구축 같은 정부 사업) |

## 5. 분류 (AI ⑤)

**AI에 넘기는 정보** (`sourceFields`, 2026-11-19 보완): 원문에서 사람이 읽을 수 있는 칸은 **모두** 넘긴다. 특징을 보고 분류하는 작업이라 단서를 빼지 않는다.
- 넘김: 이름, 설명, 지원 내용, **키워드, 대·중분류, 추가 자격 조건**, 신청·심사 방법, 제출 서류, 참여 대상 관련, 소득 조건, 기타, 나이, 지원 규모, 사업·신청 기간, 주관·운영 기관, 신청·참고 주소. 목록에 없는 칸도 한글이 있으면 원래 칸 이름으로
- 넘기지 않음: 숫자 코드(코드표 없이는 의미 없음), 지역 코드 목록, 조회수, 등록 기관·담당자, 등록·수정 시각
- 빈 칸은 넣지 않고, "입력에 없는 항목은 원문에 정보가 없다는 뜻"이라고 알려 줌
- 처음 버전은 이름·설명·지원 내용·신청 방법 등 7칸만 넘겨 키워드("맞춤형상담서비스")·분류·추가 자격 조건이 빠졌음 → 신청 방법 한 줄만 보고 난이도를 추측하는 원인이었음
- 크기: 정책 1건 평균 약 650자, 8개 묶음 최대 약 2만 2천 자 (호출 수는 그대로)

| 칸 | 내용 |
| -- | ---- |
| `actionable` | 개인이 신청·가입·이용·상담·방문할 수 있는가. **이름 규칙이 우선** (아래) |
| `summary` | 쉬운 말 1~2문장. **원문에 없는 숫자가 있으면 버림** |
| `burden` | 가장 부담 큰 방식: 온라인 / 방문 / 전화·상담 / 여럿이 함께 |
| `stage` | **참여 난이도 1~6 = 별 단계와 같은 눈금** (아래). 신청 방식의 최소값보다 낮으면 올림 |
| `difficulty_note` | 난이도 이유 한 줄 |
| `relevance` | 고립 청년에게 도움이 되는 정도 0~3 |
| `tags` | 생활비·주거·일자리·배움·마음건강·문화·여가·사람과 함께·건강·금융 중 1~3개 |

**참여 난이도**

| 난이도 | 별 단계 | 정책 기준 | 신청 방식별 최소값 |
| ------ | ------- | --------- | ------------------ |
| 1 | 집 안 | 집에서 온라인으로 끝 | 온라인 1 |
| 2 | 집 앞 | 온라인 + 문자·메일 연락 | |
| 3 | 혼자 외출 | 혼자 한 번 방문 | 방문 3 |
| 4 | 사람 있는 곳 | 기관 이용·여러 번 방문 | |
| 5 | 짧은 상호작용 | 전화·상담·면접 | 전화·상담 5 |
| 6 | 대화·참여 | 집단 프로그램·정기 참여 | 함께 6 |

**개인 이용 가능 규칙** (AI가 양쪽으로 틀린 사례가 있어 추가: 대출보증·문화시설 할인 → 사업으로, 시스템 시범 설치 → 이용 가능으로)
- 이름에 실태조사·고도화·시범 설치·모델 개발·모의적용·모니터링·위촉·기업 육성·시스템/플랫폼 구축·제도 개선·홍보 → **사업(false)**
- 이름에 대출·보증·할인·수당·지원금·바우처·이용권·공급·상담·사례관리·주거 지원·월세·패스 → **이용 가능(true)**
- 둘 다면 사업 우선, 둘 다 아니면 AI 판단

## 6. 추천 점수 (③)

| 조건 | 점수 |
| ---- | ---- |
| 관련도 | × 3 |
| 내 단계보다 높은 난이도 (바로 위 단계) | −2 |
| 전화가 부담 + 전화·상담 정책 | −3 |
| 사람 만나기가 부담 + 함께하는 정책 | −3 |
| 낯선 곳이 부담 + 방문 정책 | −1 |
| 혼자 하고 싶음 + 함께하는 정책 | −2 |
| 함께하는 활동도 보고 싶음 + "사람과 함께" 태그 | +1 |
| 손 뻗어 보기 이유 "돈이 들어서요" 있음 + 생활비·금융 태그 | +2 |
| 14일 안에 마감 | +1 |

- 사용자 값: `users.current_stage`(난이도 기준), `region_code`, `birth_year`(없으면 나이 조건 없이), `start_answers.burden`·`with`, `star_attempts.stop_reason`
- **프로필 연결은 다음 단계**: 시작 질문 저장 API가 생기면 `start_answers`·`current_stage`가 채워져 그대로 반영된다. 나이는 정책 화면에서 선택 입력 예정

## 7. 화면 (다음 단계)

- 위치: 청년센터·바깥 지도 화면의 "나에게 맞는 정책" (권장)
- 카드: 쉬운 말 요약 · 신청 방식 · 추천 이유 · 마감 · **원문 보기**(→ 클릭 기록) · 전화·방문이면 **문의 문장 준비하기**(AI ⑥) · "자격은 원문에서 확인해 주세요. 요약은 AI가 만들어 틀릴 수 있어요."
- 상단: "예시 지역: 서울 마포구 · 정책 정보 기준 {basis.updatedAt}"
- "모든 정책 보기"(`?view=all`): 난이도 거르지 않음
