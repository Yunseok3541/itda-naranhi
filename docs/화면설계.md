# 화면 설계

## 모바일 화면 개선 및 홈 화면 실행

- `mobile-flow.tsx`: 시작 중 첫 밤하늘 요청이 401이어도 데모 재시작이 성공하면 앱을 연다. 회고 입력은 401·503에서 유지하며, 저장 성공 응답 이후에만 완료 화면을 표시한다.
- `globals.css`, `layout.tsx`: 한국어 시스템 글꼴, 아이보리 배경, 하단 메뉴와 기기 안전 영역, 별자리와 같은 좌표를 쓰는 연결선.
- `manifest.json`, `favicon.ico`, `apple-icon.png`, `web/public/naranhi-*.png`: 연결된 두 별 아이콘과 standalone 실행 설정. 오프라인·알림은 제출 범위 밖이다.
- 실제 API 재현: 데모 시작 → 오늘의 별 → 가상 체크인 저장 → 추천받기 → 별 선택 → 손 뻗어 보기 → 가상 회고 저장 → 내 밤하늘 → 새로고침 → 별의 기억에서 같은 회고 확인. 최종 빌드로 통과했다.
- Edge 모바일 뷰포트 360·390·430px에서 첫 요청 401 복구, 회고 401·503 후 입력 보존·재시도, 300자 입력, 하단 메뉴, 날짜 형식, manifest 및 아이콘 응답을 확인했다. 물리 키보드·모바일 소프트 키보드, 갤럭시 Chrome·아이폰 Safari 실기기 홈 화면 설치 및 아이콘 실행은 미확인이다.
- 센터·문의 연동은 후속 작업이다. 17번 예시 별 링크는 예시 모드에서만 표시된다.

수혁 캡처 위치: 시작 화면은 새 브라우저로 `/`, 추천은 `/checkin`에서 추천받기 직후, 회고는 `/stars/[starId]` 저장 전, 밤하늘은 `/sky`에서 별을 선택한 뒤다.

## 실제 API 연동 후속 작업

- 변경 파일은 `web/src/lib/mobile-data.ts`와 `web/src/components/mobile-flow.tsx`다. 실제 API를 기본으로 선택하고 예시 모드는 체험 방식에서 선택할 수 있다.
- HTTP 오류의 상태·코드·help를 유지한다. `DEMO_SESSION_REQUIRED`, `NO_SESSION`, 401에서 데모를 다시 시작한 뒤 작성하던 글로 재시도할 수 있다. 새 세션에서는 이전 체크인 ID로 추천을 요청하지 않는다.
- 재현 순서: 데모 시작 → 한 줄 기록 → 추천 → 별 선택 → 손 뻗어 보기 → 회고 저장 → 내 밤하늘 → 새로고침 → 같은 별의 회고 확인.
- Edge 390×844 모바일 뷰포트에서 모의 응답으로 체크인 401, null 저장, help, 재시도, 빈 추천, 기본 추천, 회고 401, 세션 복구 및 새로고침 후 동일 회고 확인을 통과했다. 갤럭시·아이폰 실기기는 확인하지 않았다.
- `npm.cmd run lint`, `npm.cmd run build` 통과. 기준 `origin/master`에는 신규 데모 세션·추천·시도·밤하늘 라우트가 아직 없어 실제 저장·재조회와 후속 센터 연동은 대기 중이다.

## 모바일 시연 구현 (김재희)

- `/`: 최초 체험 방식 선택·시작 질문·데모 시작. 답변은 서버에 저장하지 않는다고 표시. 재방문에는 내 밤하늘.
- `/sky`: 별자리와 전체 별 목록, 윤곽/부분 채움/채움 및 상태 텍스트. 별 선택 시 기록 날짜·회고 표시.
- `/checkin`: 한 줄과 rest/home/near/out 선택 → 날씨 수정 → 추천 별. rest 예시는 빈 추천 확인용.
- `/stars/[starId]`: 동등한 완료·시도 선택, 사유와 회고, 중복 저장 방지, 저장 완료 후 밤하늘 재조회.
- `/centers`, `/centers/demo`: 가상 센터와 문의 초안 로컬 저장, 예시 전용 17번 별로 앞까지 가 보기 직접 기록 연결. 실제 센터 API 계약 전이며 실제 센터 방문 활동·GPS 도착 판정은 미연결. 16·17번 별에서 위치 미지원·거부 시에도 자기 보고로 기록 가능. 좌표를 저장하거나 전송하지 않음.

### 실행 및 통합

`cd web` → `npm.cmd ci` → `npm.cmd run dev`. 첫 화면에서 **예시 모드** 선택 후 데모 시작. 가상 기록은 localStorage에 새로고침 후에도 유지되며 서버 AI는 호출하지 않음. 첫 질문은 아직 추천에 반영하지 않는 예시 별자리 체험임.

실제 모드는 하단 `체험 방식 다시 선택` → **실제 API** → 데모 시작. `POST /api/demo/session`부터 호출하며 사용자 식별은 서버 세션에 맡김. 사용자 ID를 전송하거나 고정하지 않음. 모든 호출은 `src/lib/mobile-data.ts`에 있음. 실제 오류 시 예시 모드로 대체하지 않음. 기존 userId 필수 체크인 API는 세션 계약으로 백엔드 변경 필요.

공유 계약: recommendations는 `{checkinId}`, attempts는 `{starId,status,reflection,verifyMethod,stopReason?}`, sky는 `{stars}`. 현재 `verifyMethod: self` 사용. 사유 코드는 SQL에 맞춰 crowded/weather/tired/no_time/not_for_me/cost/other 사용.

### 수혁 캡처 순서

1. 최초 안내와 보라색 밤하늘.
2. 오늘 할 수 있는 별 찾기 → 가상 한 줄 입력 → 집 안 → 한 줄 기록하기.
3. 마음 날씨 선택 수정 → 오늘의 별 추천받기 → 창문 열고 하늘 보기.
4. 손 뻗어 보기 → 사유 선택 → 회고 `창문 앞까지 가 보았어요` → 이 순간 저장하기.
5. 내 밤하늘에서 기억 보기 → 새로고침 → 같은 별 선택 → 날짜·같은 회고 캡처.

추가 확인: 쉬어 가기의 빈 추천, API 모드 미구현 서버 오류, 체크인 null 저장 시 입력 유지·추천 차단·help 표시, 저장 중 재클릭 차단. API 오류·help는 실제 통합 서버 응답으로 추가 검증해야 함.

### 검증 범위

계산한 대비: 주요 버튼 #604392 / 흰 글자 7.73:1, 밝은 카드 #F4EEFA / #211735 글자 14.90:1, 기록한 별 #FFD68A / 밤하늘 12.30:1.

`npm.cmd run lint`, `npm.cmd run build` 통과. 클라이언트 모듈 검증에서 예시 체크인→추천→dim 저장→새 클라이언트 재조회 시 같은 회고 유지, rest 빈 추천, 실제 API 오류 시 실패 반환을 확인함. 브라우저 자동화 도구는 설치되어 있지 않아 실제 클릭·키보드·모바일 뷰포트는 미검증. 데이터 모듈 검증은 브라우저 새로고침 실측과 구분함.

버튼 최소 높이 48~52px, 스크롤 가능한 일반 문서 흐름에 저장 버튼 배치(키보드와 겹치는 고정 버튼 없음), safe-area 패딩 적용. 색 대비는 주요 보라 버튼/흰 글자, 밝은 카드/어두운 글자 조합을 사용. 모바일 뷰포트 브라우저 검증 및 갤럭시·아이폰 실기기 검증은 별도 수행 필요. 실제 API 성공 흐름은 아직 확인하지 않음.

> 화면은 Next.js 앱(`web/src/app/`)에 만든다 (고민기록 #27). API는 [API명세.md](API명세.md)
> 화면과 흐름은 `docs/기획/아이디어_v4.md`(3장 서비스 흐름, 4장 청년센터 상세, 9장 MVP·데모 시나리오)가 기준이다.

## 화면 목록 (MVP)

| 화면 | 핵심 요소 |
| ---- | --------- |
| 시작 질문 | 질문 3개(활동 범위 / 부담 상황 / 혼자·함께) → 시작 별자리 제안 → 선택 |
| 밤하늘 (홈) | 내 별자리, 아직 따지 않은 별·희미한 별·딴 별, 바로 위 단계 열기 |
| 체크인 | 한 줄 일기 + "오늘은 어떤 활동이 괜찮을까요?" → 마음 날씨("AI가 고른 날씨예요. 다르면 바꿔 주세요") |
| 오늘의 별 | 추천 별 1~3개 + 이유, 바깥 별은 근처 장소 |
| 별 수행 | **"하늘의 별 따기"** / **"손 뻗어 보기"** 버튼, GPS 별은 도착하면 버튼이 켜짐, `직접 도착 기록` |
| 회고·다음 행동 | 회고 한 줄 → 응원, (손 뻗어 보기면) 이유 선택 → 더 작게 / 다른 날 / 다른 별 / 마치기 |
| 별자리 완성·도감 | 완성 연출, 별을 누르면 그날의 기억(날짜 + 회고) |
| 바깥 지도 | 근처 청년센터, 참여 부담별 정책 (단계와 관계없이 언제든) |
| 청년센터 상세 | `문의 문장 준비하기` · `앞까지 가 보기` 나란히, 초안 저장 |
| 도움받을 곳 | 109, 1577-0199, 지역 청년마음건강 지원사업 (항상 접근 가능) |

## 주의할 점

- **API 응답의 `help`가 있으면 항상 안내를 띄운다** (위기 표현 감지 결과)
- `checkinId`가 `null`이면 "저장하지 못했어요" 안내 + 재시도, 입력 내용은 유지
- 위치·카메라는 **HTTPS 또는 localhost**에서만 동작 → Vercel 배포 주소에서는 동작 (로컬 확인 시 개발자 도구에서 위치 지정)
- 위치 권한 거부·실패 시 바로 `직접 도착 기록`으로 전환, 불이익·다른 연출 없음
- 별 개수·점수·순위를 화면에 강조하지 않음 (기획 원칙)
- 카카오맵 JS 키는 브라우저에 노출되므로 카카오 개발자 콘솔에 도메인 등록 필요
