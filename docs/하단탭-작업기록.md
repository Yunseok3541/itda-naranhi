# 하단 탭 작업 기록과 복구 가이드

> 브랜치 `feat/bottom-tab`에서 하단 탭을 한 단계씩 바꾸는 실험 기록
> **이 문서만 보고 혼자서도 원하는 단계로 돌아갈 수 있게** 적어 둔다
> 최신 기록은 GitHub의 `feat/bottom-tab` 브랜치에서 본다 (예전 단계로 이동하면 이 문서도 그때 내용으로 바뀌기 때문)
> https://github.com/Yunseok3541/itda-naranhi/blob/feat/bottom-tab/docs/하단탭-작업기록.md

## 1. 브랜치 구조

```
master                       팀 공용. 이 실험 중에는 건드리지 않음
 └─ fix/main-screen-fixed    메인 화면 고정 (탭 실험 전 작업, 따로 보관)
     ├─ feat/sky-background  배경 천구 뷰 (docs/배경-작업기록.md)
     └─ feat/bottom-tab      하단 탭 실험 ← 여기서 작업 (1단계 전에 feat/sky-background 3단계까지 합침)
```

- 탭 실험을 통째로 버려도 `master`와 `fix/main-screen-fixed`는 그대로 남는다
- 탭 관련 코드: `web/src/components/mobile-flow.tsx`(탭 목록 `navigation`, 탭 그리기 `bottom-nav`), `web/src/components/night-sky.css`·`web/src/app/globals.css`(탭 모양)

## 3. 복구 가이드

### 먼저 할 것 (모든 상황 공통)

터미널에서 저장소 폴더로 이동한 뒤

```bash
git status                 # ① 지금 브랜치와 저장 안 한 변경 확인
git fetch origin --tags    # ② GitHub의 최신 기록·태그 받기
git log --oneline -15      # ③ 최근 단계 목록 (위가 최신)
git tag -l "tab-*"         # ④ 태그 목록
```

- `git status`에 바뀐 파일이 보이면 **먼저 정리**한다. 남길 거면 커밋, 잠깐 치워 둘 거면 `git stash` (다시 꺼내기: `git stash pop`)
- 단계 찾기: `git log --oneline --grep "탭 3단계"`
- 다른 브랜치·단계로 이동한 뒤 **화면이 이상하면** `cd web && npm install` 후 `npm run dev`

### 상황별 방법

#### A. 방금(또는 특정) 단계 하나만 취소하고 싶다 — 가장 안전, 기록이 남음

```bash
git switch feat/bottom-tab
git revert <취소할 커밋 해시>      # 그 단계의 변경을 반대로 하는 새 커밋이 생김
git push
```

- 편집기 창이 뜨면 저장하고 닫으면 된다 (vim이면 `:wq` 입력 후 Enter)
- 충돌이 나면: 표시된 파일을 고친 뒤 `git add <파일>` → `git revert --continue`. 포기하려면 `git revert --abort`

#### B. 예전 단계를 잠깐 다시 보고 싶다 (아무것도 바뀌지 않음)

```bash
git switch --detach tab-v1         # 태그 또는 커밋 해시
cd web && npm run dev              # http://localhost:3000 에서 확인
# 다 봤으면 원래대로
git switch feat/bottom-tab
```

- "detached HEAD"라는 안내가 나와도 정상. 이 상태에서는 커밋하지 않는다

#### C. 예전 단계부터 다른 방향으로 다시 해 보고 싶다 (지금까지 기록도 보관)

```bash
git switch -c feat/bottom-tab-b tab-v1   # tab-v1 상태에서 새 브랜치
git push -u origin feat/bottom-tab-b
```

- 두 버전(`feat/bottom-tab`, `feat/bottom-tab-b`)을 모두 갖고 비교할 수 있다. **대부분 이 방법을 추천**

#### D. 브랜치 자체를 예전 단계로 되돌리고 그 뒤 단계는 버리고 싶다 (주의)

뒤 단계가 브랜치에서 사라진다. 먼저 백업 태그를 남긴다.

```bash
git switch feat/bottom-tab
git tag backup-20261119-1                # 지금 상태 백업 (날짜-번호로)
git push origin backup-20261119-1
git reset --hard tab-v1                  # 브랜치를 tab-v1로 되돌림 (저장 안 한 변경은 사라짐)
git push --force-with-lease              # GitHub 브랜치도 되돌림
```

- 마음이 바뀌면 `git reset --hard backup-20261119-1` 후 `git push --force-with-lease`
- **`master`에는 절대 하지 않는다** (팀원 작업이 사라질 수 있음)

#### E. 탭 실험을 통째로 그만두고 싶다

```bash
git switch fix/main-screen-fixed    # 메인 화면 고정까지만 있는 상태
# 또는
git switch master                   # 팀 공용 최신 상태
```

- `feat/bottom-tab` 브랜치는 GitHub에 남아 있으니 나중에 다시 꺼낼 수 있다

#### F. 실수로 뭔가 날린 것 같다

```bash
git reflog -20                       # 최근에 있었던 상태 목록 (리셋 전 상태도 남아 있음)
git switch -c rescue <찾은 해시>     # 그 상태를 새 브랜치로 살림
```

### 터미널 없이 하는 방법

- **GitHub 웹**: 저장소 → 브랜치 선택에서 `feat/bottom-tab` → Commits 를 누르면 단계별 변경 내용을 볼 수 있다. Tags 에서 `tab-vN` 시점의 코드를 볼 수 있다
- **VS Code**: 왼쪽 소스 제어(Source Control) 패널 → 아래 그래프(GRAPH)에서 커밋을 오른쪽 클릭하면 `Checkout (Detached)`(=B), `Create Branch...`(=C), `Revert Commit`(=A) 등을 고를 수 있다 (VS Code 버전에 따라 메뉴 이름이 조금 다를 수 있음)
- 병합된 PR을 되돌릴 때: GitHub의 PR 화면 맨 아래 **Revert** 버튼 → 되돌리는 PR이 새로 생김

### 하지 말 것

- `git add -A` / `git add .` 로 한꺼번에 올리기 → 비밀값이 든 파일이 같이 올라갈 수 있다. 바꾼 파일만 이름으로 `git add`
- API 키·DB 주소는 `web/.env.local`(앞에 점 있음)에만. 이 파일은 git이 무시한다
- `master`에 `reset`·`--force` 푸시

- 예전 하단 5칸에서는 어느 화면에서든 정책·청년센터로 바로 갔지만, 지금은 메인을 거쳐야 함
- "체험 방식 다시 선택"은 메인에서는 "모든 별 보기" 창 맨 아래, 다른 화면에서는 맨 아래
