# 처음 시작 안내 (온보딩 겸 튜토리얼)

> 1차: 브랜치 `feat/service-guide` (2026-11-21, PR #43). 팀 제안 "첫 설문 이후 온보딩(서비스 가이드) 단계 추가"를 기획 문서와 대조해 다듬은 뒤 구현했다.
> 2차 통합: 메뉴 안내는 버튼을 하나씩 비춘다. 첫 친구는 양자리의 별마중이다.
> 관련 문서: [기획/아이디어_v4.md](기획/아이디어_v4.md), [기능발견성-조사.md](기능발견성-조사.md), [고민기록.md](고민기록.md) #13·#31

## 1. 흐름 (2차 기준)

```
시작 질문 3개 → 내가 고른 답 → [다음]
  → 시작 안내 3장 (언제든 "건너뛰기")
     ① 환영: 나란히가 어떤 곳인지, 이번 안내에서 볼 것 3가지
     ② 양자리: 별 4개를 직접 따기 → 도감 등록 모달에서 별마중과 다른 별자리 친구를 만나는 법 소개 → 그날의 기억 카드
     ③ 하루 한 줄: 밤하늘 캐릭터 → 오늘의 별 → 한 줄 기록, 마음 날씨, 별 추천. 포인트와 별빛 상점 안내
  → [내 밤하늘 열기] → 메인(넓은 화면, 캐릭터가 보이는 곳. 지금 별자리 = 양자리)
  → 메뉴 안내: 버튼 7개를 하나씩 비추며 설명 (도움받을 곳 → 청년센터·정책 → 모든 별 보기 → 하늘 지도 → 오늘의 별(캐릭터) → 프로필 → 도감)
  → 기존 첫 안내 카드: "하늘을 끌어서 둘러보세요" → "반짝이는 별을 눌러 보세요"의 [가까이 보기]를 누르면 양자리로 확대(금색 완성 + 별마중)
```

- 양자리 별 4개(= 튜토리얼의 일): ① 숨 한 번 크게 쉬기 ② 지금 마음에 가까운 날씨 고르기(안 골라도 됨) ③ 오늘을 기억할 한 줄 남기기(비워 둬도 됨) ④ 오늘 해낸 작은 일 알아주기. 버튼을 누르면 무조건 별을 땀 → 실패·포기할 거리가 없음
- 딴 별은 일반 별과 같은 기록(자기 보고·딴 별)으로 남음 → 40P(1단계 × 10 × 4), 별의 기억(날씨 별은 "마음 날씨 · ○○", 한 줄 별은 쓴 그대로), 양자리 완성, 도감·프로필·프로필 그림에 별마중
- "건너뛰기"하면 기록 없이 메인으로 (지금 별자리는 원래 규칙대로)
- 다시 보기: 프로필 → 설정 → "사용 안내 다시 보기" (`/sky?guide=1`). 이미 딴 별은 다시 기록하지 않고 모달도 다시 뜨지 않음
- 확인·시연용: `/sky?tour=1`이면 메뉴 안내만 다시 띄움

## 2. 제안 검토: 기획과 맞춘 부분

| 제안 | 결정 | 이유 |
| --- | --- | --- |
| 세계관 소개 | **반영**. 문구는 기획의 말투로 ("내 속도로", "다 해내지 않아도 괜찮아요") | "새로운 관계를 만들어 가게 됩니다"는 참여를 정해 주는 말이라, 참여는 사용자가 고른다는 원칙(v4 2장)에 맞춰 "원할 때 천천히 이어 갈 수 있어요"로 |
| 튜토리얼 퀘스트 3개 → 별자리 완성 | **반영** (직접 해 보기) | 첫 별은 실패할 수 없을 만큼 쉬워야 함(v4 7장). 퀘스트는 앱 안에서 바로 끝나는 일로만 |
| 완성한 별자리를 도감에 자동 등록 | **2차에서 반영**: 튜토리얼의 일을 양자리 별 4개로 바꿔서, 실제로 완성하고 도감에 등록 | 1차에서는 가짜 완성 기록이 지표에 섞일까 봐 기록하지 않았음. 2차에서 양자리 별 자체를 튜토리얼의 일로 바꿔 기록이 사실과 같아짐. 별 4개는 자기 보고·앱 밖 활동 아님이라 1순위 지표(앱 밖 활동 시도)에 섞이지 않음 |
| 도감은 퀘스트와 별개로 "장소·경험을 발견해 수집" | **바꿈**: 실제 규칙대로 "별자리의 별을 모두 따면 그 친구를 만나요" | 지금 앱에서 도감은 별자리 완성으로만 채워짐 (도감 화면 소개 문구와 같게). 수집을 숙제처럼 느끼지 않게 하자는 제안 취지는 살림: "서두르지 않아도 친구들은 계속 기다려요" |
| 데일리 퀘스트 완료 시 100점 | **바꿈**: "하루 첫 체크인 +100 · 별을 처음 따면 +10~40 · 별똥별 +1" | 앱에 "데일리 퀘스트"는 없고, 100점은 하루 첫 체크인에 줌 (`lib/points.ts`). 메인 포인트 안내 문구와 같은 표현 |
| "매일 새로운 퀘스트가 기다리고 있어요" | **바꿈**: "매일 오지 않아도 돼요. 연속 기록도, 감점도 없어요" | 연속 기록 압박 없음(#31, v4 알림 원칙). 페르소나는 "연속 기록이 끊기면 자책하고 삭제"한 사람 |
| 주요 버튼·메뉴 안내 | **반영**: 메인 화면 위에서 실제 버튼을 하나씩 비추며 설명 (2차) | 버튼 설명은 실제 버튼 옆에서 보여야 기억함(기능발견성 ④·D). 1차의 한 장 코치마크는 설명이 한꺼번에 떠서 2차에서 하나씩으로 |
| 여러 화면에 걸친 흐름 (10단계) | **줄임**: 양자리 안내 3장 + 메뉴 안내, 장마다 건너뛰기 | 팀 조사에서 "여러 장짜리 소개 튜토리얼은 효과 없음"(NN/g 70명 연구). 그래서 짧게, 읽기보다 직접 해 보기, 언제든 건너뛰기로 위험을 줄임 |

지키는 것
- **도움받을 곳은 항상 보임**: 안내 중에도 위쪽 모서리 "도움받을 곳" 버튼 그대로 (v4 7장 안전장치). 메뉴 안내 첫 항목도 도움받을 곳. 한 줄 기록에 위기 표현이 있으면 도움받을 곳 안내를 띄움
- **이미 쓰던 사람에게 갑자기 뜨지 않음**: 시작 질문을 처음 마친 사람에게만. 다시 시작해도 한 번 본 안내는 다시 나오지 않음

## 4. 실제 API 배포

- 운영 DB에 `db/migrations/20261124_constellation_shapes.sql`을 적용한 뒤 별자리 11개, 별 70개, 양자리 별 4개를 확인한다. 실제 API의 밤하늘 응답에 양자리 네 별이 들어오기 전에는 세 별짜리 연습 안내가 열리고 기록·포인트를 남기지 않는다. 적용 이후 새 안내와 설정의 다시 보기에서 양자리 연습이 자동으로 열린다.
- 튜토리얼 별 67~70은 일일 별 따기 한도에서 제외한다. 기존 토끼자리 활동과 달콩 수집 기록은 유지된다.
- 별마중은 도감과 프로필 그림 선택에 등록된다. 수집 모달과 도감에서 꾸벅 인사하는 모습을 볼 수 있고, 움직임 줄이기 설정에서는 기본 그림을 보여 준다.
