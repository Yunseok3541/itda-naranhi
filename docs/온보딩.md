## 1. 흐름 (2차 기준)

```
시작 질문 3개 → 내가 고른 답 → [다음]
  → 시작 안내 4장 (언제든 "건너뛰기")
     ① 환영: 나란히가 어떤 곳인지, 이번 안내에서 볼 것 3가지
     ② 토끼자리: 아주 쉬운 별 3개를 직접 "하늘의 별 따기" → 세 별이 이어져 토끼자리 완성 → 도감 등록 모달("토끼자리 친구 달콩을 만났어요") → 그날의 기억 카드
     ③ 별자리 친구: 첫 친구 달콩 + 아직 못 만난 친구(프로필 그림 고르기와 같은 별가루 그림)
     ④ 하루 한 줄: 오늘의 별 = 한 줄 기록 → 마음 날씨 → 오늘의 별, 포인트가 쌓이는 방법·별빛 상점, 매일 안 와도 된다는 안내
  → [내 밤하늘 열기] → 메인(넓은 화면, 캐릭터가 보이는 곳. 지금 별자리 = 토끼자리)
  → 메뉴 안내: 버튼 7개를 하나씩 비추며 설명 (도움받을 곳 → 청년센터·정책 → 모든 별 보기 → 하늘 지도 → 프로필 → 오늘의 별 → 도감)
  → 기존 첫 안내 카드: "하늘을 끌어서 둘러보세요" → "반짝이는 별을 눌러 보세요"의 [가까이 보기]를 누르면 토끼자리로 확대(금색 완성 + 달콩)
```

- 토끼자리 별 3개(= 튜토리얼의 일): ① 숨 한 번 크게 쉬기 ② 지금 마음에 가까운 날씨 고르기(안 골라도 됨) ③ 오늘을 기억할 한 줄 남기기(비워 둬도 됨). 버튼을 누르면 무조건 별을 땀 → 실패·포기할 거리가 없음
- 딴 별은 일반 별과 같은 기록(자기 보고·딴 별)으로 남음 → 60P(2단계 × 10 × 3), 별의 기억(날씨 별은 "마음 날씨 · ○○", 한 줄 별은 쓴 그대로), 토끼자리 완성, 도감·프로필·프로필 그림에 달콩
- "건너뛰기"하면 기록 없이 메인으로 (지금 별자리는 원래 규칙대로)
- 다시 보기: 프로필 → ⚙ 설정 → 맨 아래 "나란히 사용 안내 다시 보기" (`/sky?guide=1`). 이미 딴 별은 다시 기록하지 않고 모달도 다시 뜨지 않음
- 확인·시연용: `/sky?tour=1`이면 메뉴 안내만 다시 띄움

## 2. 제안 검토: 기획과 맞춘 부분

| 제안 | 결정 | 이유 |
| --- | --- | --- |
| 세계관 소개 | **반영**. 문구는 기획의 말투로 ("내 속도로", "다 해내지 않아도 괜찮아요") | "새로운 관계를 만들어 가게 됩니다"는 참여를 정해 주는 말이라, 참여는 사용자가 고른다는 원칙(v4 2장)에 맞춰 "원할 때 천천히 이어 갈 수 있어요"로 |
| 튜토리얼 퀘스트 3개 → 별자리 완성 | **반영** (직접 해 보기) | 첫 별은 실패할 수 없을 만큼 쉬워야 함(v4 7장). 퀘스트는 앱 안에서 바로 끝나는 일로만 |
| 완성한 별자리를 도감에 자동 등록 | **2차에서 반영**: 튜토리얼의 일을 토끼자리 별 3개로 바꿔서, 실제로 완성하고 도감에 등록 (6절) | 1차에서는 가짜 완성 기록이 지표에 섞일까 봐 기록하지 않았음. 2차에서 토끼자리 별 자체를 튜토리얼의 일로 바꿔 기록이 사실과 같아짐. 별 3개는 자기 보고·앱 밖 활동 아님이라 1순위 지표(앱 밖 활동 시도)에 섞이지 않음 |
| 도감은 퀘스트와 별개로 "장소·경험을 발견해 수집" | **바꿈**: 실제 규칙대로 "별자리의 별을 모두 따면 그 친구를 만나요" | 지금 앱에서 도감은 별자리 완성으로만 채워짐 (도감 화면 소개 문구와 같게). 수집을 숙제처럼 느끼지 않게 하자는 제안 취지는 살림: "서두르지 않아도 친구들은 계속 기다려요" |
| 데일리 퀘스트 완료 시 100점 | **바꿈**: "하루 첫 체크인 +100 · 별을 처음 따면 +10~40 · 별똥별 +1" | 앱에 "데일리 퀘스트"는 없고, 100점은 하루 첫 체크인에 줌 (`lib/points.ts`). 메인 포인트 안내 문구와 같은 표현 |
| "매일 새로운 퀘스트가 기다리고 있어요" | **바꿈**: "매일 오지 않아도 돼요. 연속 기록도, 감점도 없어요" | 연속 기록 압박 없음(#31, v4 알림 원칙). 페르소나는 "연속 기록이 끊기면 자책하고 삭제"한 사람 |
| 주요 버튼·메뉴 안내 | **반영**: 메인 화면 위에서 실제 버튼을 하나씩 비추며 설명 (2차) | 버튼 설명은 실제 버튼 옆에서 보여야 기억함(기능발견성 ④·D). 1차의 한 장 코치마크는 설명이 한꺼번에 떠서 2차에서 하나씩으로 |
| 여러 화면에 걸친 흐름 (10단계) | **줄임**: 4장 + 메뉴 안내, 장마다 건너뛰기 | 팀 조사에서 "여러 장짜리 소개 튜토리얼은 효과 없음"(NN/g 70명 연구). 그래서 짧게, 읽기보다 직접 해 보기, 언제든 건너뛰기로 위험을 줄임 |

지키는 것
- **도움받을 곳은 항상 보임**: 안내 중에도 위쪽 모서리 "도움받을 곳" 버튼 그대로 (v4 7장 안전장치). 메뉴 안내 첫 항목도 도움받을 곳. 한 줄 기록에 위기 표현이 있으면 도움받을 곳 안내를 띄움
- **이미 쓰던 사람에게 갑자기 뜨지 않음**: 시작 질문을 처음 마친 사람에게만. 다시 시작해도 한 번 본 안내는 다시 나오지 않음

## 6. 2차 결정 기록 (2026-11-22)

- **메뉴 안내**: 한꺼번에 설명이 뜨던 한 장 → 버튼 하나씩 비추기. 카드는 첫 안내 카드와 같은 모양, 단추는 "다음" 하나(건너뛰기 없음). 배경을 밝게 하는 안은 해 보고 원래 어두기(66%)로 둠
- **첫 친구**: "튜토리얼을 끝내면 토끼자리(달콩)를 얻고 시작"하고 싶다는 요청. 처음엔 토끼자리 별이 카페·도서관·서점(바깥 활동)이라 별 기록 없이 달콩만 선물로 주는 방식을 골랐으나, 메인이 완성 화면이 아닌 점이 어색해서 **토끼자리 별 3개를 튜토리얼의 일로 바꾸는 쪽**으로 정리. 기록이 사실과 같아지고, 도감·프로필·프로필 그림이 완성 규칙 그대로 동작(서버의 프로필 그림 확인도 그대로)
- **바뀐 별**: 10 가까운 카페에서 음료 한 잔 사 마시기(GPS) → 숨 한 번 크게 쉬기 / 11 동네 도서관에서 책 한 권 펼쳐 보기(GPS) → 지금 마음에 가까운 날씨 고르기 / 29 동네 서점에서 책 구경하기 → 오늘을 기억할 한 줄 남기기. 모두 자기 보고·앱 밖 활동 아님, 단계 2 그대로. **별 ID를 그대로 둔 이유**: 생성 스크립트·동기화 SQL은 별을 지우지 않는 구조(기록 보존)라 ID를 바꾸면 동기화가 멈춤. 대신 예전 카페·도서관·서점 기록이 있으면 새 문구로 보임(시연 데이터라 허용)
- **공용 Neon 적용 필요**: `db/migrations/20261121_quests_sync.sql`을 Neon에 다시 실행해야 실제 API 모드에 반영됨 (파일 머리말 방법). 적용 전에는 API 모드의 토끼자리가 예전 문구이고, 튜토리얼 기록도 그 별에 남음
- **하루 별 따기 한도(10개)**: 튜토리얼이 첫날 한도 중 3개를 씀
- **메인 시작**: 안내 직후 메인은 넓은 화면(캐릭터·말 걸기가 보이는 곳)에서 메뉴 안내를 하고, 지금 별자리를 토끼자리로 둬서 첫 안내 카드의 "가까이 보기"로 토끼자리에 감
